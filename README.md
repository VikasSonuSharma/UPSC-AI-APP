# UPSC-AI-APP
A complete agentic ai app to help the UPSC candidates to ask questions and resolve their doubts
# Document RAG

Ask questions frm my own notes which i prepared during my UPSC preparation. The app splits the PDFs into chunks that follow their headings, stores them in a vector database, finds the passages most relevant to a question, and has an LLM write an answer with citations.

It includes:

- **`ingest.py`**: turns PDFs into a searchable index (chunking, embeddings, clustering, ChromaDB).
- **`ask.py`**: command-line question answering over the index.
- **`api.py`**: a FastAPI app with a small web page and a JSON API.

## How it works

```
Ingestion (run once)
  PDFs -> extract text -> detect headings -> heading-aware chunks
       -> embeddings -> clustering -> ChromaDB

Query time (every question)
  question -> embed -> semantic search in ChromaDB -> top matching chunks
           -> prompt (question + chunks) -> LLM -> answer + sources
```

Key design choices:

- **Heading-aware chunking.** Chunks follow the document's own sections instead of fixed-size cuts. Each chunk is embedded together with its heading path (for example `Policy > Returns > Time Limits`), which makes retrieval more accurate.
- **Metadata on every chunk.** Document name, heading path, page range and cluster ID are stored, which gives citations and filtering.
- **Clustering.** UMAP + HDBSCAN groups chunks by topic (KMeans is used automatically on very small corpora). The cluster ID can be used to narrow a search.
- **Answers use both sources.** The LLM is told to answer mainly from the retrieved excerpts, cite them as `[1]`, `[2]`, and put anything from its own general knowledge in a separate "From general knowledge:" paragraph.

## Project structure

```
.
├── ingest.py          # PDFs -> index
├── ask.py             # command-line Q&A
├── api.py             # FastAPI app + web page
├── requirements.txt
├── pdfs/              # your PDFs (not committed)
└── index/             # generated by ingest.py (not committed)
    ├── outline.txt        # heading tree of every PDF
    ├── chunks.jsonl       # all chunks with metadata and cluster IDs
    ├── embeddings.npy     # one vector per chunk
    ├── clusters.json      # cluster sizes and keywords
    └── chroma/            # ChromaDB collection "docs"
```

## Requirements

- Python 3.10 or newer
- A free API key from [Groq](https://console.groq.com/keys) (default), or [OpenRouter](https://openrouter.ai/keys), or a local [Ollama](https://ollama.com) install

## Setup

```bash
git clone <your-repo-url>
cd <your-repo-folder>

python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

pip install -r requirements.txt
```

Put your PDFs in a folder, for example `pdfs/`. The PDFs must be text-based (not scanned images).

## Usage

### 1. Build the index

First check the chunking without creating any embeddings:

```bash
python ingest.py --pdf-dir ./pdfs --out-dir ./index --chunks-only
```

Open `index/outline.txt` and compare the heading tree with your real documents. When it looks right, run the full pipeline:

```bash
python ingest.py --pdf-dir ./pdfs --out-dir ./index
```

| Option | Default | Meaning |
|---|---|---|
| `--pdf-dir` | required | folder containing the PDFs (searched for `*.pdf`, not subfolders) |
| `--out-dir` | `index` | where the index is written |
| `--max-tokens` | `600` | maximum chunk size (approximate tokens) |
| `--min-tokens` | `80` | smaller chunks are merged with neighbours |
| `--model` | `BAAI/bge-small-en-v1.5` | embedding model (sentence-transformers) |
| `--min-cluster-size` | `5` | HDBSCAN minimum cluster size |
| `--chunks-only` | off | stop after chunking, for inspection |
| `--no-chroma` | off | skip writing the ChromaDB collection |

Running it again rebuilds the index from scratch.

### 2. Set your API key

PowerShell:
```powershell
$env:GROQ_API_KEY="your_key_here"
```

Command Prompt:
```
set GROQ_API_KEY=your_key_here
```

macOS / Linux:
```bash
export GROQ_API_KEY="your_key_here"
```

The key is read from the environment. Never put it in a file you commit.

### 3. Ask questions from the command line

```bash
python ask.py                      # interactive loop
python ask.py -q "Your question"   # single question
```

| Option | Default | Meaning |
|---|---|---|
| `--provider` | `groq` | `groq`, `openrouter`, `ollama` or `anthropic` |
| `--llm-model` | provider default | override the LLM model name |
| `--top-k` | `5` | chunks to retrieve |
| `--max-distance` | `0.8` | drop chunks farther than this cosine distance (lower is stricter) |
| `--max-context-chars` | `8000` | cap on retrieved text sent to the LLM (protects free-tier token limits) |
| `--doc` | all | search only one document (file name without `.pdf`) |
| `--cluster-filter` | off | search only the cluster nearest to the question |
| `--show-chunks` | off | print the retrieved chunks, for debugging |
| `--model` | `BAAI/bge-small-en-v1.5` | embedding model, **must match `ingest.py`** |

### 4. Run the web app

```bash
python api.py
# or: uvicorn api:app --reload
```

- Web page: http://127.0.0.1:8000
- Interactive API docs: http://127.0.0.1:8000/docs

| Endpoint | Description |
|---|---|
| `POST /ask` | body: `{"question": "...", "top_k": 4, "doc": null}`; returns the answer and its sources |
| `GET /documents` | lists the ingested documents |
| `GET /health` | status, chunk count, provider and model in use |

Example:

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "What is the return time limit?"}'
```

### Configuration (environment variables for `api.py`)

| Variable | Default | Meaning |
|---|---|---|
| `GROQ_API_KEY` / `OPENROUTER_API_KEY` | none | API key for your provider |
| `LLM_PROVIDER` | `groq` | `groq`, `openrouter`, `ollama`, `anthropic` |
| `LLM_MODEL` | provider default | override the model name |
| `INDEX_DIR` | `index` | folder created by `ingest.py` |
| `EMBED_MODEL` | `BAAI/bge-small-en-v1.5` | must match the model used for ingestion |
| `MAX_CONTEXT_CHARS` | `8000` | cap on retrieved text sent to the LLM |
| `OLLAMA_HOST` | `http://localhost:11434` | Ollama server address |

Default models: Groq `openai/gpt-oss-120b`, OpenRouter `openrouter/free`, Ollama `qwen3:4b`, Anthropic `claude-sonnet-5-5` (needs `pip install anthropic` and `ANTHROPIC_API_KEY`). Free-tier model names change often. If you get a "model not found" error, pick a current model name from your provider and pass it with `--llm-model` or `LLM_MODEL`.

## Troubleshooting

| Problem | Fix |
|---|---|
| `python api.py` prints nothing | You are running an old `api.py` without the startup block, or the server is still loading the embedding model (up to a minute). |
| Old behaviour after editing code | The server only reads code at startup. Stop it with Ctrl+C and start it again. Make sure no older server is still using the port. |
| `model_not_found` (404) | The model name was retired. Set `LLM_MODEL` or `--llm-model` to a current model. |
| `413` / "tokens per minute" on a free tier | Lower `--top-k` or `MAX_CONTEXT_CHARS`, or wait a minute. |
| `No API key found` | Set the key in the **same terminal** that runs the app. |
| `hdbscan` fails to install on Windows | Use scikit-learn's built-in version: in `ingest.py` replace `import hdbscan` with `from sklearn.cluster import HDBSCAN` and `hdbscan.HDBSCAN(` with `HDBSCAN(`. Remove `hdbscan` from `requirements.txt`. |
| Garbled text or tables in chunks | Inspect `index/chunks.jsonl`. Tables extracted from PDFs can come out jumbled. |
| Headings detected wrongly | Check `index/outline.txt`. Adjust `is_heading` in `ingest.py`. |
| Chroma or search errors after changing the embedding model | Re-run `ingest.py` with the same `--model` you use for questions. |

## Privacy and security

- Your question and the retrieved excerpts are sent to the LLM provider you choose. For confidential documents use a local model (`--provider ollama`).
- The web app has no login and is meant for local use. Add authentication before exposing it on a network.
- `pdfs/`, `index/` and any `.env` file are excluded from Git by `.gitignore`.

## Limitations

- English text and text-based PDFs only (no OCR).
- Tables are extracted as plain text.
- Each question is independent (no chat memory).
- Chunk sizes use a rough word-count token estimate.
